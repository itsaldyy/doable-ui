### 🎯 Objective

The primary objective of this file is to establish a systematic documentation process for every major task, regardless of its nature (e.g., requirements analysis, system architecture, system design, software development). This documentation serves as a learning artifact and a transparent record of your work, ensuring that my understanding of the process, decision-making, and outcomes is fully aligned with yours.

### 📋 Documentation Requirements

For every major task, you must generate a comprehensive and well-structured markdown file. The file should adhere to the following sections, adapting the content to the specific task type:

#### 📁 Documentation Location

All task documentation files must be created and stored in the project root's `docs/knowledge-transfer/` directory. This centralized location ensures:
- Easy discovery and access for all team members
- Consistent organization across projects
- Clear separation from code and configuration files
- Better version control and history tracking

**File Naming Convention:** Use descriptive names that include the task identifier, such as `task-1-setup-documentation.md` or `task-2-type-definitions.md`.

#### 1. Task Summary & Goal
* **Objective:** A clear, high-level statement of the problem to be solved or the goal to be achieved. Rephrase the original request to demonstrate understanding.

#### 2. Analysis & Rationale
* **Context & Background:** Provide a brief overview of the system or business context. What existing documents or files did you reference?
* **Thought Process & Rationale:** This is the most important section. Document the key decisions made and the thought process behind them. Why did you choose this approach? What alternatives were considered?

#### 3. Deliverables & Outcomes
* **Output:** A clear statement of the final result. For a requirements task, this is the requirements document. For a design task, this is the design document. For a development task, this is the code solution and a summary of its functionality.
* **Benefits & Impact:** Explain the direct and indirect benefits of the solution or output. How does this add value to the project?

#### 4. Synthesis & Future Implications
* **Synthesis:** Summarize the key learnings or takeaways from this task. What was the most critical aspect of the solution or process?
* **Next Steps:** What are the logical next steps or potential future work that could build upon this?

### 🔄 Continuous Improvement

This file is a living document. You should refer to it before and after each task to ensure compliance with these practices. The goal is to build a detailed and insightful record of your work that serves as a valuable resource for learning and knowledge transfer.
